# [분석] 화면 목표 — 보고서 예시

이 문서는 **아직 없는 화면의 예시**다. 지금 [분석]은 표 여덟 개이고, 읽는 사람이
숫자를 눈으로 비교해 결론을 만든다. 목표는 **화면이 결론을 먼저 말하고 차트가
그것을 뒷받침하는 것**이다.

아래는 가상의 사이트 `example.com` 의 2026-06-01 수집본으로 만든 보고서다.
숫자는 지어냈지만 **구조·문장·차트 형태는 그대로 구현 대상**이다.
각 절 끝의 `> 왜 이 형태인가` 는 구현할 때 지켜야 할 근거다.

막대는 이 문서에서만 유니코드로 그렸다 — 실제 화면은 인라인 SVG다
(이 리포가 이미 `anbar`·`kpiSpark` 에서 쓰는 방식).

---

# 분석 · example.com

**2026-05-04 → 2026-06-01 · 같은 28일 기준**

## 한 줄

> 클릭이 **1,240 → 1,510 (+270)** 늘었다. 그런데 **그중 218 이 브랜드 검색**이다 —
> 논브랜드는 +52 에 그쳤고, **거래성 검색어의 전환은 0** 이다.
> 지금 손댈 자리는 트래픽이 아니라 **거래성 페이지 4장**이다.

---

## 1. 클릭이 왜 그렇게 됐나

```
이전                                                    1,240
                    ┃
  노출 효과   +310  ┃████████████████████▶
  CTR 효과     -95  ◀██████
  새 검색어    +80  ┃█████▶
  빠진 검색어  -25  ◀█
                    ┃
현재                                                    1,510
```

**노출이 늘어서 번 것**이다(+310). 수요나 색인이 좋아졌다는 뜻이니
[순위 추적]에서 어느 검색어가 올라왔는지 본다.
다만 **CTR 이 -95 를 깎았다** — 노출은 늘었는데 덜 눌렸다. 제목·설명이 손댈 자리다.

> **왜 이 형태인가** — 워터폴. 데이터의 일은 *"합이 맞는다"* 를 보이는 것이다.
> 네 항은 서로 견줄 대상이 아니라 **하나의 변화를 쪼갠 조각**이고, 합치면 정확히
> Δ클릭이 된다. 지금처럼 네 개를 따로 놓은 가로 막대는 그 합이 안 보인다.
> 색은 **발산**(플러스=patina, 마이너스=copper) — 극성이 데이터의 일이다.
> 이중축은 없다. 한 축(클릭)뿐이다.

---

## 2. 일별 추이

```
클릭   ╭─╮                              ╭──╮
      ╭╯ ╰╮      ╭╮        ╭─╮        ╭╯  ╰─╮
  ────╯   ╰──────╯╰────────╯ ╰────────╯     ╰──   62/일
      05-04                              06-01
```

주말마다 내려앉는다 — B2B 사이트의 정상 모양이다.
**5-18 의 계단**(38 → 57)은 그날 색인된 페이지 3장이 만들었다.

> **왜 이 형태인가** — 라인(단일 시리즈라 area 도 가능). 일은 *추세*다.
> 눈금은 요일 격자를 옅게 깔아 주말 골을 노이즈가 아니라 리듬으로 읽게 한다.
> 값 라벨은 **마지막 점에만** 붙인다(모든 점에 숫자를 찍지 않는다).
> 호버에 크로스헤어 + 그날의 클릭·노출·CTR.

## 3. 순위 분포 — 어디에 몰려 있고 어디로 밀렸나

```
이번  ██████ 1–3위 12   ████████████ 4–10위 24   ██████████ 11–20위 19   ████ 21위+ 8
직전  ████ 1–3위 8      ██████████████ 4–10위 28  ████████ 11–20위 15    ████ 21위+ 8
                                    ▲ +4                  ▲ +4
```

**1–3위가 +4** 늘었다(벌었다). 그런데 **11–20위도 +4** 늘었다 —
4–10위에서 밀려난 것들이다. 아래 [1페이지에서 밀려난 검색어 4건]이 그 목록이다.

> **왜 이 형태인가** — 스택 막대 두 줄(이번/직전). 일은 *부분-전체 + 변화*다.
> 구간은 순서가 있는 척도라 **발산이 아니라 순서형 색**(같은 hue, 1페이지가 짙고
> 뒤로 갈수록 옅게)을 쓴다. 구간마다 다른 hue 를 주면 "21위+"가 강조되어 거짓
> 신호가 된다. **파이 금지** — 네 조각의 미세한 변화를 각도로는 못 읽는다.
> 줄을 누르면 그 구간의 검색어와 **직전 구간**(어디서 왔나)이 펼쳐진다. (구현됨)

---

## 4. 수요 구성 — 나를 아는 사람인가

```
브랜드   ████████████████████████████████████████████  830  (55%)
논브랜드 ████████████████████████████████              680  (45%)
         └ 직전 612 (+218)                             └ 직전 628 (+52)
```

**클릭 +270 중 218 이 브랜드**다. 브랜드는 광고·입소문이 떠받치고
논브랜드는 순위·색인이 떠받친다 — **SEO 성과로 볼 수 있는 건 +52 뿐**이다.

> **왜 이 형태인가** — 가로 스택 막대 **한 줄**(둘로 나눈 100% 막대)이 기본이고,
> Δ가 이야기의 중심이라 각 조각에 직전값을 직접 라벨한다. 두 계열뿐이라
> 범례 없이 **직접 라벨**로 충분하다. 색은 categorical 두 칸(고정 순서).

## 5. 사고 싶은 사람이 오고 있나 — 의도별

```
정보성   ████████████████████████████████████  61%   클릭 921   전환   3
비교성   ██████████████                        24%   클릭 362   전환   9
거래성   ████████                              12%   클릭 181   전환   0  ⚠
탐색성   ██                                     3%   클릭  46   전환   1
```

**거래성이 181클릭인데 전환 0**이다. 트래픽이 아니라 **그 페이지들이 문제**다.
아래 [클릭은 버는데 전환이 없다]에 그 4장이 있다.

> **왜 이 형태인가** — 가로 막대(정렬된 척도) + 전환 열. 일은 *부분-전체*이지만
> 결론은 "어느 갈래가 돈이 되나"라 **막대는 클릭 비중, 숫자는 전환**으로 가른다.
> **한 차트에 두 축(클릭·전환)을 겹치지 않는다** — 스케일이 100배 다르다.
> 전환 0 인 줄만 상태색(경고)을 쓰고 아이콘·라벨을 함께 단다(색 단독 금지).

## 6. 클릭 다음에 무슨 일이 났나 — 깔때기

```
노출        ████████████████████████████████████████  48,200
클릭        ████████                                   1,510   CTR 3.1%
유기 세션   ██████                                     1,180   ← 클릭의 78%
참여 세션   ███                                          520   참여율 44%
전환        ▏                                             13   0.9%
```

**클릭 1,510 → 유기 세션 1,180**. 22% 가 사라졌다 — 페이지가 뜨기 전에 떠났거나
측정이 안 붙은 것이다. 더 큰 구멍은 **참여 44%** 다: 온 사람의 절반 이상이
아무것도 안 하고 나간다.

> ⚠ **유기 세션에는 네이버·빙도 들어간다.** GSC 클릭은 구글만이라 이 둘은 1:1 이
> 아니다 — 세션이 클릭보다 클 수도 있다. 화면이 이 문장을 반드시 달아야 한다.

> **왜 이 형태인가** — 깔때기(가로 막대를 단계 순으로). 일은 *단계별 감소*다.
> **이중축을 피하는 정석**이기도 하다: 노출(만 단위)과 전환(십 단위)을 한 축에
> 놓되 각 단계에 **직전 대비 %** 를 직접 라벨해 절대값 스케일 차이를 읽게 한다.
> 단일 hue 순서형(위가 옅고 아래가 짙게) — 단계는 identity 가 아니다.

---

## 7. 클릭은 버는데 전환이 없다

| 페이지 | 클릭 | 유기 세션 | 참여율 | 전환 |
|---|---:|---:|---:|---:|
| `/pricing` | 210 | 168 | 31% | **0** |
| `/product/pro` | 148 | 121 | 38% | **0** |
| `/compare/vs-acme` | 96 | 78 | 41% | **0** |
| `/signup` | 64 | 52 | 22% | **0** |

네 장 다 **거래성**이다. 원인은 이 데이터로 모른다 — 페이지를 열어
전환 동작까지 가는 길이 있는지, **전환 이벤트 태그가 이 페이지에도 붙어 있는지**
부터 본다(태그가 안 걸렸을 수 있다).

> **왜 이 형태인가** — 표. 네 줄뿐이고 각 줄이 **행동 대상**이다(차트로 만들면
> 누를 것이 사라진다). 줄을 누르면 할 일·페이지 링크·AI 프롬프트가 펼쳐진다.
> `> 7개 클래스가 넘고 각 항목이 의미를 가지면 표` 규칙 그대로.

## 8. 기기 — 순위와 전환을 겹쳐 본다

```
             순위(GSC)          전환율(GA4)
데스크톱   ●───────  6.2위      ●──────── 1.4%
모바일     ────●     11.8위     ──●       0.3%
           나쁨   좋음          나쁨   좋음
```

모바일이 **순위도 5.6칸 아래고 전환율도 1/4** 이다.
한쪽만 나쁘면 우연이지만 **둘 다 나쁘면 페이지 자체**다.

> **왜 이 형태인가** — 덤벨 두 벌(같은 항목의 두 상태). 일은 *항목 간 비교*다.
> 순위와 전환율은 단위가 달라 **한 축에 못 놓는다** — 그래서 **작은 배수**
> (small multiples)로 나란히 놓고 각자 자기 축을 갖는다. 이중축 대신 이 방법이다.
> 두 지표가 같은 방향(모바일이 아래)일 때만 결론 문장을 낸다.

---

## 9. 국가 — 타깃 밖이 얼마나 먹고 있나

```
한국     ████████████████████████████████████  71%   전환 12
미국     ██████████                            19%   전환  1
일본     ███                                    6%   전환  0
기타     ██                                     4%   전환  0
```

타깃(한국) 밖이 **노출의 29%** 를 먹지만 전환은 1 뿐이다.
그 몫을 빼고 CTR·순위를 다시 보면 실제 성적은 이 화면 숫자보다 낫다.

> **왜 이 형태인가** — 가로 막대 + 전환 열(5번과 같은 규칙).
> 상위 3 + "기타" 로 접는다 — **9번째 나라에 새 색을 만들지 않는다.**

## 부록 A — 차트 공통 규칙

이 리포의 기존 토큰을 쓴다. 새 팔레트를 만들지 않는다.

| 항목 | 규칙 |
|---|---|
| 색의 일 | 순서형(크기)=단일 hue 명암 · 발산(극성)=patina/copper + 중립 회색 · categorical=고정 순서 |
| 금지 | 이중축, 파이(2~4조각 포함), 무지개, 순위에 따라 색 바꾸기, 모든 점에 숫자 |
| 마크 | 얇게, 데이터 끝 4px 라운드, 선 2px, 마커 ≥8px, 인접 채움 사이 2px 간격 |
| 라벨 | 선택적 직접 라벨. 계열 2개 이상이면 범례 항상, 4개 이하는 직접 라벨도 |
| 글자색 | 값·라벨·범례는 먹색 토큰. **계열 색을 글자에 쓰지 않는다** |
| 호버 | 라인·영역은 크로스헤어+툴팁, 막대·점·셀은 마크별 툴팁. 기본으로 넣는다 |
| 상태색 | 좋음/경고/심각은 예약. 계열 색으로 재사용 금지, 아이콘·라벨과 함께 |
| 접근성 | 표 보기 제공, 다크모드는 자동 반전이 아니라 같은 램프에서 다시 고른 값 |
| 검증 | categorical 팔레트는 `validate_palette.js` 로 **돌려서** 확인. 눈으로 판단 금지 |

## 부록 B — 지금과의 차이 (역설계 목록)

| # | 지금 | 목표 | 크기 |
|---|---|---|---|
| 1 | 원인 네 항이 따로 놓인 가로 막대 | **워터폴** — 합이 Δ클릭임이 보인다 | 중 |
| 2 | 일별 추이가 개요에만 있음 | [분석]에도 · 요일 격자 · 크로스헤어 | 소 |
| 3 | 순위 분포가 이번 값만 | **이번/직전 두 줄** 스택 + 순서형 색 | 중 |
| 4 | 브랜드/논브랜드가 표 두 줄 | **한 줄 스택** + 직전값 직접 라벨 | 소 |
| 5 | 의도별이 표 | 막대(클릭 비중) + 전환 열, 전환 0 경고 | 중 |
| 6 | 노출·클릭·세션·전환이 흩어져 있음 | **깔때기 한 장** + 단계별 % | 대 |
| 7 | — | GSC↔GA4 **1:1 아님** 문장 (필수) | 소 |
| 8 | 기기 격차가 GSC 순위만 | 순위 × 전환율 **덤벨 작은 배수** | 중 |
| 9 | 국가별이 표 | 막대 + 전환, 상위 3 + 기타 | 소 |
| 10 | 화면이 표만 주고 결론은 사람이 만듦 | **맨 위 "한 줄"** — 셋을 엮은 결론 | 대 |
