## 설계에서 정한 것 — 다음에 바꾸기 전에 읽을 것

### 기회는 "다시 안 나왔다"만으로 닫지 않는다

`upsert_opportunities` 는 이번 회차에 다시 나온 기회의 `run_id` 만 갱신하므로, 다시 안
나온 기회를 닫으면 될 것처럼 보인다. **그러면 살아 있는 기회를 닫는다.** 함정 둘:

- 원천 회차가 불완전하면(AI 체크가 잔액·한도로 중간에 멈춤) 못 잰 대상의 기회가 안 나온다.
- 상위 N개만 내는 종류(`ai_gaps` 의 LIMIT, `XAI_LIMIT`)는 순위에서 밀리기만 해도 안 나온다.

그래서 "다시 안 나옴"은 후보로만 쓰고, **새롭고 완결된 데이터가 조건 해소를 긍정 확인할
때만** 닫는다. 확인할 규칙을 정의할 수 없는 종류는 자동 해소에서 뺀다.

### `resolved` 와 `done` 은 다르다

`done` 은 우리가 작업해서 끝난 것, `resolved` 는 저절로 풀린 것이다. 둘을 섞으면 저절로
풀린 것을 우리 작업 효과로 세서 전후 비교가 오염된다. `resolved` 는 효과 측정에 넣지 않는다.

### 지면 묶음은 읽을 때만 한다

DB 에는 키워드마다 기회 하나(사실)를 두고, 같은 지면의 변형은 목록을 읽을 때 묶는다.
데이터 모델을 바꾸면 키워드 단위로 도는 자동 해소와 부딪히고, 읽는 쪽 묶음은 되돌리기 쉽다.

### 사이트는 나누지 않았다

영어 키워드의 언어 표시만 바로잡았다. `theotherskin-en` 을 따로 세울지는 정하지 않았다 —
어느 쪽이든 영어 키워드는 en 로케일이어야 하므로 표시 수정은 먼저 해도 맞다.

## 갈래

1. DataForSEO 402 한도 → 기다렸다 재시도, 기본 간격에 여유, 쪼개기 깊이 상한
2. AI 판정 — 질문별 최신 **성공** 측정, "측정 안 됨" 드러내기, 관련도, 질문 버전
3. 기회 자동 해소(긍정 확인) + `resolved` 상태 + 머지 동기화로 완료 반영
4. AI 요약 기회를 지면 단위로 묶기(읽는 쪽)
5. 키워드 언어 판정 + 마이그레이션, 잘못된 로케일로 잰 순위 기록 표시
6. 죽은 런의 brain `runs` 행 닫기, 연결된 사이트 한 번에 받기

질문 분류 오류("피부과에서 자주 하는 시술"이 브랜드로)는 화면에서 이미 고칠 수 있어서
이번엔 안 했다.
