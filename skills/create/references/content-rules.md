# 콘텐츠 실행 레시피 (kind → 행동) & 내장 작성 규칙

## kind별 레시피

### striking_distance — 기존 페이지 보강 (신규 생성 아님)
1. 대상 쿼리로 랭크 중인 페이지를 프로필의 URL 패턴으로 역추적해 파일을 연다.
2. **최소 diff 원칙**: 타이틀·H1·meta description에 쿼리 의도 반영, 본문에
   빠진 하위 의도 섹션 1~2개 추가, 내부링크 보강. 전면 재작성 금지.
3. 커밋 메시지에 근거 수치 요약 (예: "imp 1,840·pos 7.8 → 상단 공략 [opp #12]").

### ai_citation_gap — 질문 직답형 신규 콘텐츠 (AEO 구조)
1. 미인용 프롬프트(질문)를 제목 또는 도입 질문으로 삼는다.
2. 구조: **첫 문단에서 질문에 직답** → 근거·데이터 → 비교표(경쟁 대안 포함,
   공정하게) → FAQ 2~3개. 인용을 따내는 건 "질문에 바로 답하는 페이지"다.
3. 리포가 스키마를 쓰고 있으면 FAQPage/HowTo 구조화 데이터를 관례대로 추가.
4. Brain의 cited_domains(누가 대신 인용되는지)를 보고 그들이 답하지 못한
   각도(실데이터, 최신성, 한국어 맥락 등)를 차별점으로 잡는다.

### pseo_pattern — 템플릿 + 데이터 대량 페이지
1. 프로필의 pSEO 메커니즘(다이나믹 라우트 + 데이터 파일)을 사용. 없으면
   최소 구조(데이터 파일 1개 + 라우트 1개) 신설을 별도 커밋으로 제안.
2. **가드레일 (capture scoring.md 1b절과 동일 계약):**
   - data-rich 필수 — 페이지마다 고유 실데이터(수치·표·구체 정보)가 있어야 함.
     템플릿 문장만 바뀌는 얇은 페이지는 만들지 않는다.
   - 단계적 롤아웃 — 1차 배치 최대 10~20페이지. 색인·노출 확인
     (다음 capture gsc 런) 후 확장.
   - 슬러그·타이틀·메타는 슬롯 값별로 자연스럽게 변주 (기계적 반복 금지).
3. 데이터 출처를 데이터 파일 주석 또는 PR 본문에 명시.

### rank_decay — 리프레시
1. 하락 페이지의 낡은 부분(날짜, 스크린샷, 죽은 링크, 구버전 정보) 갱신.
2. frontmatter의 날짜 필드 관례(updated vs date)를 따라 갱신 표기.
3. 원인 가설(경쟁 등장? 시즌성?)을 PR 본문에 한 줄 — 단정하지 않는다.

### 수동 브리프 모드 (Brain 없음/비어 있음)
사용자 브리프를 인터뷰(주제, 타겟 쿼리/질문, 목적) → 위 레시피 중 성격이
가장 가까운 것을 적용. creations 기록은 opportunity_id 없이 남긴다.

## 내장 작성 규칙 (전문 절차 팩 미설치 시 기본값)

- 검색 의도 우선: 페이지 하나 = 의도 하나. 의도가 갈리면 페이지를 나눈다.
- 도입 3문장 안에 핵심 답. 결론을 뒤로 미루지 않는다.
- 주장에는 근거: Brain 수치는 "(GSC 07-21 기준)"식 표기, 제품 사실은
  리포·문서에서 확인된 것만. **없는 수치·후기·사례를 만들지 않는다.**
- 제목·메타: 타겟 쿼리 포함하되 자연문. 클릭베이트 금지.
- 내부링크: 신규 글 → 관련 기존 글 2~3개, 그리고 기존 글에서 신규 글로의
  역링크 1개 이상 (고아 페이지 방지).
- 보이스: 프로필의 보이스 요약을 따른다. 기존 글과 나란히 두었을 때
  이질감이 없어야 한다.
