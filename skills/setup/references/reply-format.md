# 답변 형식 — 스킬이 채팅으로 돌려주는 모든 말

setup·capture·create 가 작업을 끝내고 사용자에게 하는 말은 **같은 뼈대**를 쓴다.
매번 다른 모양으로 답하면 사용자가 매번 새로 읽어야 하고, 정작 "그래서 다음에
뭘 치나"가 문단 어딘가에 묻힌다.

## 뼈대 — 이 네 칸, 이 순서

```
**{한 줄 결론}**

| {측정한 것} | {값} |
|---|---|
| … | … |

**다음 한 걸음** — `{명령 하나}`
{왜 그게 다음인지 한 줄}

<details><summary>안 한 것 · 건너뛴 것 N개</summary>
- …
</details>
```

1. **한 줄 결론** — 무엇이 어떻게 됐는지 한 문장. 굵게. 여기만 읽어도 되게 쓴다.
   (doctor 의 `verdict` 와 같은 물건이다 — CLI·화면·채팅이 같은 말을 하게.)
2. **근거** — 숫자는 표로, 3~6행. 근거가 두세 개뿐이면 표 대신 불릿 두세 줄.
   Brain 조회인지 즉석 조회인지 밝힌다 (capture 철칙 1). 숫자가 없으면 이 칸을 뺀다 —
   채울 게 없는데 표를 만들지 않는다.
3. **다음 한 걸음** — **정확히 하나.** 복사해서 바로 칠 수 있는 형태로.
   선택지를 늘어놓지 말고 하나를 고른 뒤, 다른 길은 아래 `<details>` 로 접는다.
   (판정의 정본은 `capture/scripts/stage.py` 다 — 내가 다시 판단하지 않고 그 결과를 배달한다.)
4. **안 한 것** — 건너뛴 단계·유료 축·못 한 것. **접어서** 한 곳에 모은다.
   항목마다 "안 하셔도 됩니다"를 반복하지 않는다 — 요약 줄에서 한 번만 말한다.
   빈손이면 이 칸을 통째로 뺀다.

## 실패했을 때

같은 뼈대에 칸 하나만 바꾼다 — 결론 자리에 **막힌 지점**, 다음 걸음 자리에 **우회로**.

```
**{어디서 막혔는지 한 줄}** — {가장 짧은 결정적 에러 문장 그대로}

**다음 한 걸음** — `{복구 명령}`
{지금 당장 되는 다른 것이 있으면 한 줄로}
```

에러 문자열·명령·경로는 원문 그대로. 스택트레이스와 CLI 출력 전문은 붙이지 않는다
(사용자가 `/setup doctor` 처럼 전문을 명시해 요청했을 때만).

## 하지 말 것

- **CLI 출력을 통째로 옮겨 적기.** 스크립트가 이미 찍은 표를 채팅에 다시 그리지 않는다 —
  한 줄 결론과 다음 걸음만 말하고 화면/파일로 넘긴다.
- **문단으로 설명하기.** 긴 산문은 플러그인이 아니라 챗봇처럼 느껴진다
  (2026-08-18 사용자 피드백).
- **다음 걸음 여러 개 나열하기.** 두 개 이상이면 하나를 고르고 나머지는 접는다.
- **같은 항목을 두 곳에 적기.** 근거 표에 있는 걸 아래 문장으로 또 말하지 않는다.
- **내부 용어 그대로 쓰기.** 치환표는 `../SKILL.md` 의 말투 규칙 절.

## 스킬별로 채우는 것

| 스킬 | 한 줄 결론 | 근거 표 | 다음 한 걸음 |
|---|---|---|---|
| `setup` | doctor `verdict` 그대로 | 지금 되는 기능 / 사이트 연결 상태 | doctor `next_command` |
| `capture` | 무엇을 몇 건 모았나 | 수집량·상위 기회 3~5행 (Brain 근거) | `stage.state()` 의 `here` 단계 명령 |
| `create` | 어떤 기회를 어떤 파일로 바꿨나 | 변경 파일·브랜치·PR·닫은 기회 id | 다음 기회 또는 `/capture run` |
