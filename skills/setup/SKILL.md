# setup — seo-miner 최초 온보딩 & 환경 닥터

역할: "지금 뭐가 되고, 뭐가 빠졌고, 다음에 뭘 하면 되는지"를 진단하고 순서대로
고쳐준다. 추측 금지 — 항상 doctor부터.

## 말투 규칙 (사용자에게 보이는 모든 문장에 적용)

SEO를 처음 하는 사람이 읽는다고 가정한다.
- 내부 용어를 그대로 말하지 않는다: brain→보관함, capability→기능,
  OAuth→구글 로그인 연결, striking distance→조금만 밀면 1페이지 갈 키워드.
- 항목마다 "이걸 하면 뭐가 좋아지는지"를 한 줄로 붙인다. 소요 시간과
  유료/무료 여부도 같이 말한다.
- 안 해도 되는 건 **한 통에 모아 한 번만** "안 하셔도 됩니다"라고 말한다.
  항목마다 반복하면 부담을 줄이려던 문구가 화면을 "못 하는 것" 목록으로 채운다 —
  doctor 가 [꼭 해야 할 일] 아래 [더 켜고 싶으면] 한 통으로 찍는 이유다.
  같은 항목을 두 곳에 적지 않는다(잠긴 기능 + 나중에 할 것에 유료 키가 두 벌
  들어가 있었고, 한쪽이 낡아 없어진 문서 절을 가리키고 있었다).
- 명령어는 사용자가 그대로 복사해 붙일 수 있는 형태로만 준다.

## 답변 형식 (채팅으로 나가는 모든 말)

한 줄 결론 → 근거 표 → **다음 한 걸음 하나** → 접어 둔 "안 한 것". 이 뼈대와
실패 시 변형, 하지 말 것은 `references/reply-format.md` 하나가 정본이다 —
여기 다시 적지 않는다.

## 표준 경로 — 사이트 하나를 붙이는 전체 순서

**공통 1회** (컴퓨터당 한 번)
1. `/setup` → doctor 실행 → 빠진 게 있으면 doctor가 [꼭 해야 할 일] 1번에 찍은
   설치 명령을 내가 대신 실행(명령 문자열의 정본은 `scripts/doctor.py` 의
   `CORE_PIP` — 여기 옮겨 적지 않는다). 보관함은 자동 생성이라 따로 만들 게 없다.
   (직접 클릭해서 하고 싶다면 `/setup web` — 아래 "화면으로 할 때". 사이트 등록·
   인증 파일 회수·API 키까지 그 화면에서 끝난다.)
   **웹을 먼저 쓰던 사람인가 — 여기서 한 번만 묻는다.** 플러그인은 설치해도
   호스팅과 자동으로 안 이어진다(플러그인은 사용자가 누구인지 모른다 — 신원은
   웹이 발급한 토큰뿐이다). 보관함이 비어 있고 호스팅 연결도 없으면 doctor 가 [꼭 해야 할 일]
   1번에 "웹에서 이미 쓰고 계셨나요?" 를 찍는다 — 그렇다고 하면 아래 "명령어로
   연결하기"(웹 [설정]의 한 줄)를 받아 내가 대신 실행하고, 3번 이후의 사이트 등록은
   건너뛴다(이미 웹에 있다). 아니라고 하면 그대로 3번으로 간다. 진단 맨 아래
   "호스팅 연결:" 줄이 지금 상태의 정본이다.
2. **마케팅 스킬 팩 — 첫 리포트가 나온 뒤에 권한다.** doctor가 위임 스킬의 설치
   여부를 보고, 빠진 게 있으면 **[선택]** 버킷(화면 머리말 "더 켜고 싶으면")에
   올린다 — [꼭 해야 할 일]이 아니다. **어떤 스킬 몇 개인지는 여기 적지 않는다** —
   명부가 정본이다(`scripts/doctor.py` 의 `ALL_SKILLS`, 목록은
   `../capture/references/external-skills.md` 표).
   **첫 세션에서 먼저 꺼내지 마라.** 설치가 끝나면 Claude Code 재시작이 한 번
   필요한데, 온보딩 중의 재시작은 제일 비싼 중단이고 정작 측정·수집에는 이 팩이
   필요 없다. 8번(첫 리포트)까지 온 다음에 "글의 각도를 더 깊게 잡으려면" 으로
   권하면 그때는 재시작 값을 한다.
   사용자가 먼저 물으면(또는 8번을 지나면) "제가 대신 설치할까요?" 라고 묻고,
   승낙 시 `python scripts/install_skills.py` 를 실행한다 (무료 — 재시작 필요를
   같이 알린다). 거절하거나 넘어가면 내장 규칙으로 진행한다 — 작업을 거부하지
   않는다. 출처 저장소(`https://github.com/coreyhaines31/marketingskills`)도 같이
   알려 둔다 — 사용자가 화면을 닫은 뒤에 다시 따라갈 수 있는 유일한 기록이다.
   이 단계는 사이트마다가 아니라 **컴퓨터당 1회**다.

**사이트마다 반복** (여기부터는 사이트 단위)

3. **GSC 연결(필수) — 등록보다 먼저 하는 쪽이 낫다.** 아래 "GSC 연결" 절차.
   **콘솔 작업은 없다** — 플러그인이 OAuth 클라이언트를 동봉하므로 남은 건 브라우저
   **로그인 한 번**뿐이다(무료, 계정당 1회). 사이트를 추가해도 이 절차는 다시 하지
   않고, 속성마다 권한을 주는 단계도 없다.
   자동 수집 + Claude가 `gsc_query.py` 로 즉석 조회.
   실적(클릭·노출)이 이 도구의 재료라 연결 없이는 측정이 시작되지 않는다.
   (CSV 내보내기 임시 경로는 2026-08-18 제거.)

   **왜 등록보다 먼저인가:** 로그인해 두면 `gsc_query.py properties` 가 실제 속성
   목록을 준다 — 등록 인터뷰에서 `gsc_property` 표기(`sc-domain:` vs `https://`)를
   사용자에게 묻지 않아도 되고, 추정이 틀려 첫 수집이 빈손으로 끝나는 일도 없다.
   로그인 창을 지금 못 여는 상황이면 순서를 바꿔도 된다 — 4번이 추정값으로
   등록하고 로그인 뒤에 대조한다.
4. `/capture add {사이트}` — 인터뷰 3문항(타입·도메인·시드 키워드). `gsc_property`는
   3번의 목록에서 고른다. `collect_gsc.py`가 프로젝트의 `gsc_property`를 Brain에서
   읽으므로 **등록 전에는 수집이 안 된다** — 수집은 반드시 이 단계 뒤다.
5. `/capture keywords {사이트}` → 키워드 유니버스 채우기.
   **3번을 아직 못 했으면 이걸 먼저 돌린다** — 인증도 키도 안 쓰는 유일한 수집이라
   첫 수확을 로그인 앞으로 당길 수 있다. 로그인 전에 `/capture run` 을 돌리면
   1단계에서 중단되어 빈손으로 끝난다.
6. **포지셔닝 문서 만들기** — 아래 "마케팅 문서" 절. 1회, 무료.
7. **[선택]** AI 인용 확인 — `/capture ai {사이트}` (OpenRouter 키 필요).
   **첫 바퀴의 관문이 아니다** — 키가 없으면 8번의 `run` 이 이 단계만 건너뛰고
   계속 돈다(`capture/scripts/run_all.py` 의 `check_paid_keys`). 키가 없는 사용자를
   여기 세워 두지 마라. 막는 것은 3번(무료 구글 로그인) 하나뿐이다.
8. `/capture run {사이트}` → 리포트까지 한 번에. **여기까지가 첫 바퀴다** — 리포트에
   "1페이지까지 몇 칸 남았는지"가 찍히는 게 이 도구를 쓰는 이유이므로, 앞 단계에서
   막히면 우회로(5번 먼저)를 써서라도 여기까지 오게 한다.

4번을 건너뛰고 수집을 하려 하면 `collect_gsc.py`가 프로젝트를 못 찾고 멈춘다.

## 워크플로우

### 1. 진단 — 기본은 화면이다
`python scripts/doctor.py` (이 스킬 폴더 기준) 실행. stdlib 전용이라 pip 이전에도 돈다
(경로·env는 옆 스킬의 `capture/scripts/db.py`에서 읽지만 그 모듈도 stdlib뿐이다).

doctor는 위임 스킬 설치 여부도 본다(명부: `scripts/doctor.py` 의 `ALL_SKILLS` —
개수와 이름을 여기 다시 적지 않는다). 빠진 게 있으면 doctor가 **[선택]** 에 올린다
(첫 리포트 전에는 밀지 않는다 — 위 표준 경로 2번). 사용자가 물어보거나 첫 바퀴가
끝났으면 그 문장을 그대로 전달하고 "제가 대신 설치할까요?" 라고 묻는다. 승낙 시
`python scripts/install_skills.py` 를 실행한다 (성공 후 Claude Code 재시작이
한 번 필요함을 같이 알린다). 거절 시 내장 규칙으로 진행한다 — 작업을 거부하지
않는다. 자세한 규칙은 `../capture/references/external-skills.md` 의 (a)~(d)를
따른다. **doctor 의 문구를 여기 다시 적지 않는다** — 두 벌이 되면 한쪽만 낡는다.

**진단 결과를 채팅에 통째로 옮겨 적지 마라.** 채팅에는 한 줄 요약(verdict)과
다음 한 걸음 하나만 말하고, 곧바로 `python scripts/doctor.py --web`을
**백그라운드로** 띄워 대시보드에서 보게 한다 — 진단 배너·[설정] 패널·[안내]
6단계가 화면에 다 있고, 키 등록도 폼에서 직접 한다. 긴 텍스트 설명은
플러그인이 아니라 챗봇처럼 느껴진다 (2026-08-18 사용자 피드백).
CLI 텍스트 전문이 필요한 경우는 사용자가 `/setup doctor`라고 명시했거나
브라우저를 못 여는 환경일 때뿐이다.

**웹을 띄우기 전, 등록할 사이트가 아직 없고 현재 폴더가 콘텐츠 레포로 보이면
씨앗 프리필을 먼저 쓴다** — 첫 사이트 폼의 판단 칸(씨앗 키워드 등)이 미리
채워지도록. 레포의 README·주요 페이지 제목·frontmatter·콘텐츠 주제를 2~3분
훑고 `~/.capture/prefill.json`에 저장한다 (폼은 빈 칸만 이 값으로 채우고,
등록이 성공하면 파일은 자동 삭제된다):

```json
{"name": "mysite", "domain": "mysite.com", "type": "saas", "locale": "ko-KR",
 "seed_keywords": ["실제 사용자가 칠 검색어 8~15개 — 레포 콘텐츠에 근거"],
 "brand_aliases": ["사이트 이름 표기들"],
 "tools": ["레포가 다루는 남의 도구·경쟁 브랜드 이름들"],
 "competitors_manual": ["경쟁 도메인 — 확실한 것만"]}
```

씨앗은 창작이 아니라 **레포에 실제로 있는 주제**에서만 뽑는다 (없는 주제의
키워드를 넣으면 이후 모든 측정이 그 허상을 쫓는다). 확신 없는 키는 빼라 —
빈 키는 폼에서 그냥 빈 칸이다.

`locale` 은 **레포 콘텐츠의 언어**로 채운다 — 한국어 회사의 영어 사이트면
`en-US` 다. 고를 수 있는 값은 `skills/capture/scripts/serp_adapter.py` 의
`LOCALES`(폼의 언어-지역 선택지가 그 표다). 그 값이 SERP 나라·자동완성·AI 질문
언어를 전부 정하므로, 채팅으로 온보딩할 때는 "어느 언어·나라의 검색 결과에서
잴까요?" 를 한 번 묻고 폼에서는 사용자가 목록에서 바꾼다.

**화면 모드 상세**: `python scripts/doctor.py --web` — 로컬 대시보드를 띄운다.
상단 배너가 같은 진단이고, 그 아래 [설정] 패널에서 **채팅 없이 직접** 할 수 있다:
기본 부품 설치 · 첫 사이트 등록(폼) · 받은 구글 인증 파일 회수 · API 키 저장
(`~/.capture/env`에 저장 — 셸 rc를 편집시키지 않는다).
사용자가 "화면으로/대시보드로 해줘", "채팅 말고 직접 하고 싶다"고 하면 이걸
**백그라운드로** 실행하고(포그라운드는 세션을 막는다) 어느 칸을 채우면 되는지만
말해준다. 내 판단용 데이터는 계속 CLI/`--json`을 읽는다.

화면에서 **안 되는 것**은 구글 로그인(사용자 계정 조작이라 브라우저 창이 한 번
열린다)과 AI 프롬프트 초안 생성(판단이 필요해 채팅 몫)뿐이다. 폼으로 만든
프로젝트는 프롬프트가 비어 있으므로, 등록 후 `/capture add {P}`의 5단계(프롬프트
초안)만 채팅에서 이어서 해준다. 폼은 `gsc_property`를 도메인에서 추정하므로
`/capture add` 2번의 대조(`gsc_query.py properties`)도 한 번 해 준다.

**웹에서 이어 하기** — 사용자가 "자동으로 계속 재게 해줘", "매번 명령 치기 싫다",
"다른 기기에서도 보고 싶다"고 하면 화면 [설정]의 **6. 웹에서 이어 하기**를 알려준다.
링크 한 번으로 여기 등록한 설정 그대로(도메인·종류·씨앗·브랜드·경쟁사) 호스팅에
등록되고, 유료 키는 서버가 댄다. **먼저 꺼내지 마라** — 첫 바퀴(표준 경로 8번)가
끝나기 전에는 옮길 것도 없고, 로컬에서 뭘 얻는지 본 뒤에야 판단이 선다.
측정한 자료는 안 넘어간다는 것(웹이 처음부터 다시 잰다)을 반드시 같이 말한다.

**명령어로 연결하기** — 웹으로 옮긴 뒤 "그래도 여기서 치던 대로 하고 싶다"고 하면
화면 [설정]의 **명령어로 연결하기**를 알려준다. 거기서 나오는 한 줄을 채팅에 그대로
붙여 주면 내가 `PLUGIN_DIR` 자리를 채워 실행한다. 연결 뒤에는 **명령이 하나도 안
바뀐다** — 같은 `/capture ...` 가 웹에 등록한 사이트를 돌리고, 서버가 찍은 결과를
그대로 받는다(달라지는 것은 `../capture/SKILL.md` 의 "원격(호스팅) 사이트").
로컬에서 첫 바퀴를 돈 사람에게는 **먼저 꺼내지 마라** — 웹에 옮긴 뒤의 이야기다.
예외는 하나: 보관함이 비어 있고 연결도 없으면 doctor 가 표준 경로 1번에서 먼저
묻는다(웹을 먼저 쓰던 사람은 여기가 시작점이다).
그 한 줄에는 토큰이 실려 있으니 다른 데 옮겨 붙이지 말라는 것과, 토큰은 그 화면에서
한 번만 보이고 다시 만들면 전에 받은 것이 끊긴다는 것을 같이 말한다.

### 2. 수리 — next steps를 위에서부터, 하나씩 확인받고 실행
- **pip 설치**: 사용자 확인 후 직접 실행해준다. 보관함(brain.db)은 첫 실행 때
  자동 생성되므로 init을 시키지 않는다.
- **[선택] 항목은 밀지 않는다.** doctor가 [선택]으로 분류한 건 "지금 안 해도 된다"고
  분명히 말한다. 단 GSC 연결은 [선택]이 아니라 필수다 — doctor가
  [꼭 해야 할 일]에 올린다.
- **API 키**: 직접 발급해줄 수 없는 항목. 정확한 절차는
  `../capture/references/setup.md`(5·7절)를 읽어 단계별로 안내하고,
  받은 키는 **아래 "키를 어디에 두는가"대로 `~/.capture/env`에** 넣게 한다
  (값 자체는 사용자가 넣게 — 키를 채팅에 붙여넣지 않도록 권한다).
- 각 수리 후 doctor를 재실행해 ✗→✓ 전환을 확인시킨다.

### 2-b. 키를 어디에 두는가 (여기 한 곳뿐)
`~/.capture/env` 에 `KEY=VALUE` 한 줄씩. 모든 스크립트가 `db.load_env()`로 이 파일을
읽으므로 셸 rc를 편집시키지 않는다 — 대시보드 [설정]의 키 칸도 여기에 쓴다.
이미 셸에서 `export` 해 둔 값이 있으면 그쪽이 이긴다(`load_env`는 setdefault라
환경변수를 덮어쓰지 않는다). 그래서 CI·임시 세션에서는 export로 갈아끼울 수 있다.

### 3. 단계적 활성화 안내 (키 0개로도 거의 다 된다는 걸 먼저 말한다)

무엇이 켜져 있고 무엇이 무슨 키로 열리는지의 정본은 **doctor 의 준비 상태 명부**다
(`scripts/doctor.py` 의 `CAPABILITIES` — 항목마다 이름·한 줄 설명·무료/유료·
키 이름·발급 URL·고치는 문구가 한 벌씩 있고, 화면과 `--json` 의 `readiness` 가
그걸 그대로 렌더한다). **목록을 여기 다시 적지 않는다** — 두 벌이 되면 한쪽만 낡고,
낡은 쪽이 사용자에게 없는 할 일을 시킨다(이 문서가 실제로 겪었다).

여기서 정하는 건 **말하는 순서**뿐이다:

1. 키 0개로도 대부분 된다고 **먼저** 말한다 — doctor 의 `지금 되는 것` 줄 그대로.
2. 그다음 구글 연결 하나만 필수라고 말한다 (무료, 로그인 한 번).
3. 유료 키는 [선택] 통에 **모아서 한 번만** 말한다. 발급처는 명부의 `url` 을 쓴다.

### 3-b. "이제 뭘 하냐"는 질문
말로 순서를 읊지 말고 대시보드 [안내]를 띄운다 — 6단계와 **그 프로젝트가 실제로
어디까지 왔는지**(스냅샷 수·발굴 키워드 수·기회 수)가 Brain 기준으로 찍히고
"지금 할 것" 하나가 표시된다. 그 명령만 대신 실행해 주면 된다.

### 3-c. 어느 사이트를 말하는지 모를 때 — 묻는다, 고르지 않는다

보관함(`~/.capture/brain.db`)은 **컴퓨터 전역**이다. 사이트가 여럿이면 "지금 이 폴더가
어느 사이트냐"는 자동으로 안 정해진다. 판정의 정본은 `stage.pick_project()` 이고
순서는 하나뿐이다: **이 폴더의 리포 매치 > 사이트가 하나뿐이면 그것 > 못 고름**.

doctor 가 못 고르면 `[꼭 해야 할 일]`에 그 문장을 올리고 `다음 한 걸음`을 비운다.
그때 **아무 사이트나 골라서 진행하지 마라** — 사용자는 그게 이 폴더의 사이트인 줄 안다
(다른 리포에서 `/setup` 을 돌렸는데 늘 먼저 등록한 사이트가 떴다는 신고가 이것이다).
할 말은 셋 중 하나다:

- 등록된 이름 중 하나면 → 이름을 물어보고 그 사이트로 진행한다.
- 이 폴더가 새 사이트면 → `/capture add <원하는이름>`.
- **매번 안 묻게 하려면** → 이 폴더에서 `/create profile <이름>` 을 한 번 돌린다.
  `$CAPTURE_HOME/projects/{이름}.repo.yaml` 의 `repo_path` 가 기록되고, 다음부터
  이 폴더(와 하위 폴더)에서 자동으로 그 사이트가 붙는다.

대시보드는 화면에서 고른 사이트를 `/api/doctor?project=` 로 같이 보내므로 이 모호함이
없다 — 사용자가 직접 고른 것이 폴더 추론을 이긴다.

### 4. 졸업
core ✓ + 프로젝트 0개면 → `/capture add <이름>` 으로 자연스럽게 넘긴다
(구글이 이미 붙어 있으면 `gsc_query.py properties` 목록을 들고 간다 — 표기를
물어볼 필요가 없어진다).
프로젝트가 있고 구글도 붙었으면 → `/capture run <이름>` 제안.
프로젝트는 있는데 **구글이 아직이면 `/capture keywords <이름>` 을 먼저** 제안한다 —
풀런은 1단계에서 멈춰 빈손으로 끝나고, 자동완성은 인증 없이 지금 결과를 준다.

## 마케팅 문서 — 사이트당 1회, 무료

사이트를 등록하고 나면 **그 사이트가 무엇이고 누구에게 무슨 약속을 하는지**를
문서 하나로 만든다. 이게 없으면 capture 의 AI 질문도, create 의 글도 매번
바닥부터 추측한다 — 같은 사이트를 두고 런마다 다른 말을 하게 된다.

절차 (`/capture add` 인터뷰 직후, 또는 사용자가 "포지셔닝 잡아줘"라고 할 때):

1. `product-marketing` 스킬이 있으면 그 스킬로 만든다. 넘기는 재료는 인터뷰에서
   이미 받은 것들이다 — 사이트 타입·도메인·시드 키워드·브랜드 별칭·경쟁사·도구 이름.
   **새로 인터뷰하지 않는다**(같은 걸 두 번 묻는 게 제일 싫은 경험이다).
2. 스킬이 없으면 **먼저 설치를 권한다** — 이 스킬은 이 문서를 만들어 준다.
   출처는 `https://github.com/coreyhaines31/marketingskills`. 사용자가 설치를
   원치 않거나 넘어가겠다고 하면 (3) 으로 간다 — 작업을 거부하지 않는다. 같은
   세션에서 두 번은 조르지 않는다.
3. 설치를 거절했거나 넘어갔으면 인터뷰 답변을 그대로 정리한 요약본을 쓴다.
   형식은 같다: 한 줄 정의 · 대상 · 해결하는 문제 · 경쟁 대비 다른 점 · 쓰는
   말과 안 쓰는 말. 결과에 "이 부분은 내장 규칙으로 처리했습니다"를 한 줄 남긴다.
4. `$CAPTURE_HOME/docs/{사이트}/positioning.md` 로 저장한다 (`db.docs_dir()`).
   Brain(brain.db) 이 아니라 파일인 이유는 **사람이 직접 고쳐야 하는 것**이라서다.
5. 앱 스토어 리스팅이 있는 사이트면 `aso` 스킬로 `aso.md` 도 같이 만든다. 그
   스킬도 같은 규칙으로 먼저 설치를 권한다. 거절했거나 사이트에 앱이 없으면
   건너뛴다 — 웹만 있는 사이트에 억지로 만들지 않는다.

사용자에게 할 말: "한 번만 만들어 두면 이후 글·AI 질문이 전부 이걸 기준으로
나갑니다. 사이트가 크게 바뀔 때만 다시 만들면 됩니다."

나머지 위임(seo-audit·ai-seo·content-strategy·site-architecture·programmatic-seo·
schema)은 측정이 쌓인 뒤 capture/create 가 부른다 — 셋업 단계에서 미리 부르지
않는다. 계약 전문: `../capture/references/external-skills.md`.

## GSC 연결 — 남은 건 로그인 한 번뿐이다

"GSC 연동해줘"라고 하면 **콘솔 절차를 읽어주지 마라.** 그 절차는 이제 없다.
플러그인이 자기 OAuth 클라이언트를 동봉하므로(`skills/setup/oauth_client.json`),
사용자가 구글 클라우드 콘솔에서 할 일은 **0**이다.

기본 절차 (무료, 계정당 1회):

1. `python ../capture/scripts/collect_gsc.py --project {P}` 를 돌린다.
   **이때 브라우저 로그인 창이 한 번 열린다.** 구글 계정으로 로그인하면 끝이다.
2. 동의 화면에 **"Google에서 확인하지 않은 앱"** 경고가 한 번 뜬다 —
   `고급` → `...(으)로 이동`. **이걸 미리 알려라.** 아무 예고 없이 이 화면을 보면
   대부분 거기서 멈춘다.
3. 끝. 내가 소유한 속성이 전부 붙는다. 속성마다 '사용자 및 권한'에 이메일을
   추가하는 단계는 **없다** — 그건 서비스 계정에만 있던 절차다.

로그인으로 받은 토큰은 `~/.capture/gsc_token.json` 에 저장되고, 벌크 수집
(`collect_gsc.py`)·즉석 조회(`gsc_query.py`)·색인 검사(`collect_index.py`)가 같이
쓴다 — 인증은 한 벌이다(방식 판정의 정본은 `db.gsc_auth()`, 연결 판정의 정본은
`db.gsc_connected()`). 예전 gsc MCP 서버 자리에 토큰이 남아 있으면 그대로
승계하므로, 이미 로그인한 사람은 다시 로그인하지 않는다.

정직하게 알릴 것: 동봉 클라이언트는 구글 심사를 받지 않은 앱이라 (a) 위 경고 화면이
있고 (b) **사용자 100명 상한**이 있다. 토큰이 만료되면 로그인 창이 다시 한 번 뜨는
게 전부다(재설치 아님).

로그인 화면이 뜨면 멈추고 사용자에게 넘긴다. 인증 파일 **내용을 화면·대화에 찍지
않는다** — 특히 client_secret 은 로그에도 남기지 않는다.

### ⚠️ 파일이 있다 ≠ 연결됐다 (3-상태)

번들 클라이언트는 **설치만 하면 항상 존재한다.** 그래서 "OAuth 클라이언트 파일이
있다"가 더 이상 "연결됐다"를 뜻하지 않는다. 이 함정은 이 파일이 아래에서 이미
경고하는 것과 **같은 종류**다 — 예전 gsc MCP 서버가 인증 없이도 `Connected`로 떠서
사용자가 한 번도 인증되지 않은 채 지냈던 그 일(실측). **doctor도 나도 같은 거짓말을
하면 안 된다.** 진짜 판정은 **토큰이 있느냐**다.

| 상태 | 조건 | 사용자에게 할 말 |
|---|---|---|
| **연결됨** | `db.gsc_connected()` | 수집 가능 — `/capture gsc` |
| **로그인 대기** | 인증 방식은 잡혔는데 토큰이 없음 | "구글 로그인 한 번만 하면 됩니다" → 위 1번 실행 |
| **인증 없음** | `db.gsc_auth() == ""` | 번들이 빠진 배포다 — 클라이언트를 직접 놓아야 한다(아래) |

`python scripts/connect_gsc.py --status` 로 지금 상태를 확인한다.

### 자기 OAuth 클라이언트를 쓰고 싶으면 (선택)

경고 화면과 100명 상한이 싫으면 자기 클라이언트를 쓴다. 사용자 것이 번들을 이긴다.
콘솔에서 **데스크톱 앱** OAuth 클라이언트를 하나 만들고(API 사용 설정 → OAuth 동의
화면 → 클라이언트 만들기), 화면의 두 문자열만 넘긴다 — JSON 다운로드가 필요 없다:

```
python scripts/connect_gsc.py --client-id <ID> --client-secret <SECRET>
```

JSON 파일을 이미 받았다면 인자 없이 실행하면 다운로드 폴더에서 회수한다
(브라우저 자동화는 크롬 다운로드를 트리거하지 못한다 — 2026-07-26 실측, 좌표 클릭·
요소 클릭·Enter 전부 실패. 그래서 다운로드 버튼은 사람이 누른다).
받은 게 서비스 계정 키면 스크립트가 판별해 그쪽 자리에 깐다.

**시크릿을 채팅에 붙여넣게 하지 마라** — 명령은 사용자가 자기 터미널에서 실행한다.

### 무인 수집이 필요하면 — 서비스 계정 갈래 (선택)

서버·스케줄러에서 사람 없이 돌려야 하면 서비스 계정을 쓴다. 만료도 로그인도 없는
대신 **속성마다 이메일을 추가하는 클릭이 생긴다.**

| | 구글 계정 로그인 (기본) | 서비스 계정 (무인) |
|---|---|---|
| 콘솔 준비 | **없음** — 클라이언트를 플러그인이 동봉 | API 사용 설정 + 서비스 계정 + 키 |
| 속성마다 권한 추가 | 없음 — 소유한 속성이 한 번에 붙음 | 속성마다 1회 필요 |
| 첫 조회 | 브라우저 로그인 창 1회 (+ 미검증 앱 경고) | 없음 (완전 무인) |
| 만료 | 만료되면 재로그인 1회 | 없음 |

절차 (동의 화면·OAuth 클라이언트는 필요 없다):

1. **Search Console API 켜기** — 위 절차 1번과 같다.
2. `console.cloud.google.com/iam-admin/serviceaccounts` → `서비스 계정 만들기` →
   이름 아무거나 → 만들기. **역할(권한) 부여는 건너뛴다** — Search Console
   접근권은 구글 클라우드가 아니라 Search Console 쪽에서 준다.
3. 만든 계정 클릭 → `키` 탭 → `키 추가` → `새 키 만들기` → `JSON` →
   **`만들기` 버튼은 사용자가 직접 누른다**.
4. `python scripts/connect_gsc.py` — `~/.capture/gsc_service_account.json`으로
   설치하고, 서비스 계정 이메일과 속성별 '사용자 및 권한' URL을 출력한다.
5. 속성마다: 출력된 URL → `사용자 추가` → 4의 이메일 → 권한 **`제한된 사용자`**
   (읽기 전용이라 충분). 다운로드가 아니므로 이 클릭은 내가 대신 해줄 수 있다.
6. `python ../capture/scripts/collect_gsc.py --project {P}` 로 첫 수집 확인.

우선순위는 **사용자가 직접 놓은 것 > 번들**이다(`db.gsc_auth()`): 자기 OAuth
클라이언트(`~/.capture/gsc_oauth_client.json`) → 서비스 계정 키 → 번들. 번들이
서비스 계정보다 뒤인 건 의도한 것이다 — 안 그러면 무인 수집을 걸어 둔 사람이
설치만으로 브라우저 로그인에 끌려간다. 무인으로 고정하고 싶으면
`~/.capture/gsc_oauth_client.json`을 치우면 된다.

  [꼭 해야 할 일]에 직접 찍는다. 그 문장을 그대로 전달한다(여기서 다시 쓰지 않는다 —
  두 벌이 되면 한쪽만 낡는다).
- **"인증 파일은 있는데 수집이 안 된다"면 십중팔구 '로그인 대기'다** — 번들
  클라이언트는 항상 있으니 파일 유무로 판단하지 말고 `--status`(=`db.gsc_connected()`)를
  본다. 할 말은 하나: "구글 로그인 한 번만 하면 됩니다."
- 동의 화면에서 막혔다면: **"Google에서 확인하지 않은 앱"** 경고다.
  `고급` → `...(으)로 이동`으로 지나간다. 이 화면 자체를 피하고 싶으면 위
  "자기 OAuth 클라이언트" 갈래.
- **`액세스 차단됨: 이 앱의 테스트가 완료되지 않았습니다`는 위 경고와 다른 것이다** —
  지나갈 방법이 없다. 클라이언트의 동의 화면이 **'테스트 중'** 이라 등록된 테스트
  사용자만 로그인되는 상태다. 번들 클라이언트에서 이게 뜨면 **배포가 깨진 것**이다:
  클라이언트 소유자는 자기 계정이라 통과하므로 개발 중에는 안 드러나고, 남이 처음
  써 볼 때야 드러난다. 고치는 쪽은 사용자가 아니라 **클라이언트 소유자**다 —
  콘솔 → API 및 서비스 → OAuth 동의 화면 → **앱 게시**(프로덕션).
  자기 클라이언트를 쓰는 사람이면 자기 콘솔에서 같은 곳을 보면 된다.
- GSC 수집이 403(권한 거부)이면: 먼저 `python scripts/connect_gsc.py --status`로
  어느 방식이 걸렸는지 본다. 서비스 계정이면 그 속성에 이메일이 아직 추가 안 된
  것(같은 명령이 이메일·속성별 URL을 다시 띄워준다). 구글 계정 로그인(기본)이면
  그 속성이 로그인한 계정 소유가 아닌 것 — 소유 계정으로 다시 로그인하거나,
  Search Console에서 내 계정을 그 속성에 추가한다.
- 로그인 창이 다시 뜨거나 토큰 만료 오류면: 토큰이 만료된 것 — 그냥 다시 로그인하면
  된다(자기 클라이언트 + 테스트 모드 동의 화면이면 7일마다 그렇다). 반복이 귀찮으면
  서비스 계정 갈래로.
- **로그인 창이 안 열리면 `google-auth-oauthlib` 부품이 없는 것이다.** 조회용
  `google-api-python-client` 와 다른 패키지다 — 없으면 수집이 "구글 로그인 부품이
  없습니다"로 멈춘다. 설치 명령은 doctor 가 `구글 실적 읽기` 잠금 사유로 찍는다
  ([더 켜고 싶으면] 통 — 정본은 `scripts/doctor.py` 의 `GSC_PIP`).
  서비스 계정 갈래는 로그인이 없어 이 부품 없이도 돈다.
- 즉석 조회가 안 되면 수집과 같은 인증을 보므로 원인도 같다 — 위 항목들을 그대로
  따른다. 확인 한 줄: `python ../capture/scripts/gsc_query.py properties`.
- 구버전 사이트별 OAuth 잔존물(`~/.capture/creds/{사이트}/`)은 더 이상 안 읽는다 —
  지워도 되고, 위 절차로 새로 붙이면 그만이다.
- 자동완성 실패 지속: 비공식 엔드포인트 특성 — 스로틀 상향(`--throttle 1.0`) 안내.
